Tests worth building

1. Garden post office

Adapt the video's sales-lead / support routing example at 00:42. Identical messages arrive as envelopes; each choice sends an envelope to Billing, Technical, or Sales. Misroutes and late envelopes remain visible. Dials: arrival rate, burst size, context length, number of choices, questions per request.

Measure: labeled accuracy, p50/p95 response time, correct-and-in-time rate, backlog, successful routes per second.

2. Twin raccoon reactions

Extend the voice-expression demo at 02:05. One live voice / transcription session supplies identical finalized transcript segments to both engines. Scripted corrections such as “crazy week … in a GOOD way” test reaction changes.

Measure: transcript-to-first-painted expression, correction-to-correct-expression delay, agreement, stale reactions and unnecessary expression flips.

3. Plush robot attention

Adapt the robot demo at 03:05 using moving apples, gamepads and other objects. Give both engines the same timestamped object descriptions and positions. They select an object ID; the same controller turns each head. “Follow the fruit” or “follow the object used for gaming.”

Measure: target selection, change-to-lock time, stale-target rate, and tracking error. This compares semantic selection over supplied descriptions, not visual recognition.

4. Agent checkpoint

An animated helper carries proposed tool actions through Allow, Ask, and Block gates. Give both engines the same explicit policy and sandboxed command descriptions. Nothing actually executes.

Measure: policy agreement, false allows, false blocks, review rate and response time. Useful for comparing a real agent decision layer.

A fair live comparison

Use the same text, choices, case IDs and deadlines. Feed both engines the same prerecorded stream before testing interactive worlds. Report every timeout, refusal and routing error. Compute completed-reply percentiles alongside the fraction of all cases that were correct and arrived in time. Keep late completions measurable even after they lose permission to act; only explicit hang timeouts should end a benchmark request.

Vercel's current OpenAI-compatible Decisions endpoint accepts openai/gpt-6-luna-decisions and typesafe-ai/jev. Using it for both reduces differences in client code and gateway hops; provider routes can still differ. Log the resolved model/provider, cache status when exposed, usage and cost. Disable fallbacks and automatic retries for the baseline. Run a separate direct-OpenAI transport control.

Jev accepts text / JSON state and does not accept images or audio. Vercel's compatible Decisions endpoint currently rejects image input. Keep native OpenAI vision as a separate capability demonstration.
